# B38: Validate final explicit field aliases

Branch `fix/invalid-explicit-aliases`; baseline `ba0b9571c324e85f2c6b21f1490ecf13f379e7ba`. This corrective commit follows `4f71692a47d8f2d81cade082ac739dd2465496b0` and supersedes that commit's raw-name validation policy.

Explicit string aliases retain their existing resolution, spelling and final transformations. The parser captures the selected alias and original wire name before constructing a model, detects raw duplicates before `DataModel` can discard a field, then validates the actual emitted names after existing field transformations. Final checks include snake-case and Python NFKC collisions, syntax errors, Pydantic's invalid fields and effective generated protected namespaces, and actual msgspec `field(...)` helper shadowing. A repeated declaration of the same wire field remains distinct from two wire fields colliding.

The previous universal reserved-name policy rejected valid output. Baseline-valid Pydantic shadows (`dict`, `json`, `copy`, `schema`, `validate`, `model_fields`), warning-only protected prefixes, configured and inherited namespace overrides, standalone msgspec `field`, and raw aliases that existing Pydantic normalization makes valid (`class`, `not-valid`, empty string) are preserved. External custom bases are not imported to guess their protected namespaces. GraphQL diagnostics use the wire alias because its existing `original_name` can contain the resolved name.

B45 integration boundary: `parser.base._ALIAS_RESOLUTION_CLASS_NAME_KEY` is `_alias_resolution_class_name`. JSON Schema records the raw resolution class when aliases are configured. B45 should update that marker only for final-class overrides before `_create_data_model`; the selected explicit-alias marker is refreshed there, including clearing stale string provenance for list aliases. Final names are validated later, so a valid final override can replace an invalid raw fallback. No public API, formatter, template, output ordering or normal naming policy changes.
